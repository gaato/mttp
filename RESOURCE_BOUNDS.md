# Resource bounds

What a long-running client, server or parser built on `gaato/mttp`,
`gaato/mttp_async` or `gaato/mttp_digest` can accumulate, and
what keeps each structure from growing without limit. The rule: **every
structure that grows with input from the network, a peer, or the number of
requests, buckets, connections or pending calls is listed here with its
bound**. A new one, such as a map keyed by names that arrive from outside or a
buffer filled from a stream, needs a row before it ships.

A bound is either a limit the code enforces, or the rate of the input times
how long an entry lives, where both are themselves bounded. Rows of the second
kind say what that product is. Bounded by default: a limit has a default, and
input past it is refused rather than degraded.

A body that may be compressed has two bounds, and each gets its own row: the
bytes read from the wire (enforced by the connection engine) and the bytes
after decoding (enforced by the decoder and the mttp client). One row for both
would hide a decompression bomb that stays under the wire limit.

**Every row of "Enforced limits" names a test that checks the bound**, in its
Tests column: a backticked file path, then the quoted names of that file's
tests, as in `` `mttp/src/h1/head_test.mbt`: "first", "second" ``. A test
counts only if it drives the structure to its limit and one past it, or pins a
default the row states; one that merely uses the feature does not.
`scripts/bounds_check.mbtx`, run by `scripts/gates.sh`, enforces the naming: it
fails when a row names no test or a named test is not declared in the named
file. Whether a named test really reaches the bound is checked in review. The
other tables describe where no limit is enforced, so they stay prose.

Test helpers (`gaato/mttp/sim`, `gaato/mttp/driver`, `gaato/mttp/testing`)
record what a test feeds them and are not listed, except the limits that keep
a test from hanging.

## Bounded by rate and lifetime

| Structure | Grows with | Bound |
|---|---|---|
| `mttp/client/ratelimit` retained state, aliases and pace deadlines | New bucket/server/group keys per millisecond, capped at 4096 per map | Live state, including fallback copies: key arrival rate × at most one hour; aliases: bucket arrival rate × one hour independently of shared-state refresh, except capacity-deferred expirations retain their route while constraints remain live; pace: group arrival rate × at most Int.MAX milliseconds (caller-configured). Sweeps on acquire/release at doubling thresholds (floor 64) or after 60 seconds reclaim expired entries, including after a burst; idle instances retain at most the hard map caps. Checked by `mttp/src/client/ratelimit/rate_limit_wbtest.mbt` ("one-off buckets leave no gates and only unexpired states behind", "a burst's expired states go once traffic settles on one bucket", "responses without rate-limit headers still sweep expired states", "one-off aliased and paced buckets keep the maps bounded") and `mttp/src/client/ratelimit/bounds_wbtest.mbt` ("aliases expire even while their shared server window keeps refreshing"); capacity deferral by `mttp/src/client/ratelimit/alias_wbtest.mbt` ("alias expiry at state capacity retains its route until transfer has room"). |
| `mttp/h1client` queued slot tickets (`Slots`, `SlotState.waiting`) | Sends that find no free slot under a configured cap | One ticket per waiting send, removed when it is granted, when the pool limit or the attempt deadline runs out, on close and on cancellation, so the queue holds at most the sends started within the longest wait (`pool_timeout_ms`, or the caller's own deadline); unset limits leave the wait, and so the queue, to the caller. Checked by `mttp/src/h1client/pool_test.mbt` ("a queued request leaves no slot behind on timeout, close or cancellation", "active connection caps queue requests until a slot frees") |

## Left to the caller

Growth that follows what the caller asks for, not what the network sends.

| Structure | Grows with | Why it is not bounded here |
|---|---|---|
| `mttp_async/runtime` VirtualClock waiters | Sleeps started by the test | A test helper: at most one waiter per outstanding sleep, removed on cancellation or when fired; settle has a separate scheduling-round bound above. |
| `mttp_async/runtime` gate and signal waiters | Calls the application starts | One waiter per concurrent acquire/wait, removed on completion or cancellation; core owns the cancellable queues. Gate capacity is caller-configured and extra releases do not increase it. |
| `http` headers, URL strings, attribute maps and byte bodies | Values explicitly constructed by the caller | Parsers and engines impose the network input limits; these value constructors do not consume network input. |
| `http` URI builder | Caller-provided components | Interpolation is linear in the supplied text and stages one query parameter. |
| `mttp/h1` payload pieces of one `ChunkedDecoder::feed` and the bytes of a written head | The bytes the caller feeds in one call; the fields the caller writes | The decoder returns copies of the payload bytes of that call and keeps none of them; the writers serialize caller-built values and validate them. |
| `mttp/h1server` background jobs | Work handlers start through the caller-supplied `@http.background` scheduler | The caller owns their scheduling and lifetime; `serve_conn` advertises the attribute only when supplied. |
| `mttp_async/server` background jobs and `mttp_async/fetch` aggregate jobs; host process trackers | Work explicitly scheduled by application handlers | No count limit on application-created jobs; server joins them on shutdown under `drain_ms`, fetch settles its aggregate after all work ends, Lambda awaits it, and process hosts expose `whenIdle`. Applications bound their scheduling and await process shutdown. |
| `mttp/driver` ready queue, live-task map, timer heap | Tasks the test spawns and timers it arms | A test helper: the test decides how many; `max_steps` stops a run that keeps spawning. Cancelled timers stay in the heap until they reach its top or `run` ends. |
| `mttp/sim` recordings and queues: `FakeClock::slept`, `ScriptedConn` writes and script, `ScriptedDialer` connections, dials and TLS hosts, `SimConn` pipes, `SimGate` waiters, `Feed` script | What the test writes, scripts and spawns | Test helpers: the test decides how much; a `SimConn` write never blocks, so a test that floods one end without reading the other grows its pipe. |
| `mttp/jsonkit` builders and decoded fields | Fields the caller writes; a JSON tree already parsed | The builder grows only with the caller's writes; decoders read a tree whose bytes the reader that parsed it bounded. |
| `mttp/sse` events returned by one `feed` or queued by `SseReader` | The chunk the caller feeds or the body source returns | Each event is bounded above, and each takes at least six bytes of input (`data`, a line end and a blank line). The reader drains the current chunk's events before reading another. |
| `mttp/multipart` framing and part descriptors | Caller-supplied parts | Framing and in-memory bodies are what the caller passed; a stream body holds the part streams and the part being read, and the boundary scan above. |
| `mttp/client` request plans, `to_curl` diagnostics and `Attempt` reports | Caller-built requests, headers and byte bodies; one `Attempt` per attempt | Plans hold what the caller set; `to_curl` encodes byte bodies with constant expansion and never reads a stream or calls a body factory; attempts are bounded by the retry count. None consumes network input. |
| `mttp/client/retry` decisions and Retry-After values | One response's headers | Decisions are pure and keep nothing; the Retry-After parsers read one header value, linear in its length, and saturate the result. |
| `mttp/schema` schemas, definition maps and issue arrays | Codecs and schemas the caller composes; a JSON tree already parsed | Definition maps grow with the named types the caller defines. A decode collects every issue; the built-in codecs add at most eight per step (an object's missing fields), so the step budget bounds them too. |
| `mttp/apispec` documents | The records the caller builds or a JSON tree already parsed | Plain data: decoding follows the document's structure, and the bytes of a parsed document were bounded by whoever read them. |
| `mttp/router` route table, middleware and definition findings | Endpoints and middleware registered by the application | Construction consumes caller-built definitions; per-request captures have the segment bound above. |
| `mttp/openapi` projected document and `mttp/endpoint/testkit` verification findings | Endpoint definitions composed by the application | Projection and checking scale with registered metadata. Each operation has at most 400 explicit final statuses (200–599) plus default; a dynamic variant fans out only across those entries. Reference traversal has its own bound above. |
| `mttp/client/ratelimit` gate waiters | Concurrent calls in one pace group | One waiter per caller, removed on handoff or cancellation; active group entries disappear once there are no holders or waiters. The caller bounds concurrent calls and their lifetime, using the Client total deadline or an injected Timer. |

## Known gaps

Growth the library does not bound yet, with what limits it in practice and how
it could be fixed.

| Structure | Grows with | What limits it | Suggested fix |
|---|---|---|---|
| `mttp/h1server` handler lifetime with `handler_timeout_ms = None` (the design's explicit default) | Time an application spends without returning or pulling its body; peer failure cannot be detected once raw read-ahead reaches 64 KiB | Configuring a finite handler deadline; request-body deadlines start only on a pull. `disconnect_test.mbt`: "a full unread body read ahead stops at 64 KiB and the handler deadline cancels it" | Propose a finite default handler deadline in the design before changing `ServerLimits::default()`; keep `None` as explicit opt-out for long-running handlers |
