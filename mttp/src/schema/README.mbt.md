# Schema and codecs

Codecs carry their JSON Schema and collect input issues with escaped JSON
pointer paths. Named children become references and retain their definitions.

```mbt check
///|
test {
  let age = @schema.int.validate(@schema.minimum(0))
  assert_eq(age.decode("42"), 42)
  let names = @schema.array(@schema.jstring).body()
  assert_eq(names.decode(b"[\"one\",\"two\"]"), ["one", "two"])
}
```

`option` treats absent fields and explicit null alike; `presence` preserves
the distinction using `jsonkit.Presence`. Object encoders omit absent values.
`object1` through `object8` use typed getters and constructors. Their code is
generated by the repository's `scripts/gen_schema_objects.mbtx`.

JSON body parsing rejects duplicate keys, limits nesting to 128 and retains
number lexemes so `jint64` can represent the full signed range exactly.
Recursive codecs also cap decoding depth (128 by default). Byte limits belong
to the HTTP reader or the caller supplying buffered bytes.

`pattern` implements a bounded subset of ECMA Unicode pattern syntax without
flags. Its schema contains the original source. It refuses unsupported syntax
when built, including lookarounds, backreferences and group repetition; see
the API documentation for exact limits. Dot excludes the four ECMA line
terminators and whitespace escapes use the ECMA whitespace set.
The anchor behavior follows the
[ECMAScript assertion semantics](https://tc39.es/ecma262/multipage/text-processing.html#sec-compileassertion).

Union case projections and injections must be inverses and cover every value
passed to encoding. Tagged payload encoders must produce objects; violating
these application-side encoding preconditions aborts. Decoding untrusted JSON
returns structured failures. Union definitions reject duplicate tags and
require between 1 and 64 cases.
